# 監査（`npm run audit`）

実物の RFC 49 本に不変条件 23 種を当てる。

```sh
npm run build && npm run audit
npm run audit -- --rfc 1123          # 1 本だけ
npm run audit -- --generation 1980s-text
npm run audit -- --update            # 基準値を書き換える
```

## 単体テストとの違い

`npm test`（vitest）は、私が書いた入力に対する assert である。書いた通りに
動くかを確かめる。監査は実物の RFC に当てて、**想定していない書式で破れる場所**
を出す。v0.6.9 以降で見つかった不具合は、すべて後者だった。

| 見つけ方 | 見つかるもの |
|---|---|
| 単体テスト | 書いた条件の取りこぼし |
| 監査 | 書かなかった書式（世代・表・擬似コード） |
| 出力見本（`npm run snapshot`） | assert に落とせない見た目の崩れ |

## RFC の本文

`tests/audit/.cache/<番号>.<xml|text>` に置く。初回だけ rfc-editor.org から
取得し、以降は使い回す（`.gitignore` 済み）。

## 基準値（`baseline.json`）

破れの件数を RFC ごとに記録する。増えたら失敗（終了コード 1）、減ったら報告する。

基準値に残っているものは、直せないと判断したものである。

| 条件 | RFC | 残っている理由 |
|---|---|---|
| D1 | 1866 | 原文が「section 7.6.1」と書くが、§7.6 までしか無い |
| D1 | 2616 | 原文が「(section 3.6.2)」と書くが、§3.6.1 までしか無い |

どちらも原文の誤りで、パーサ側で直せるものではない。
